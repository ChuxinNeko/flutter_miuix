## 平台/原生差异处理(platformConcerns)
1) Predictive back / NavigationBackHandler (androidx.navigationevent): use Flutter PopScope (3.44 onPopInvokedWithResult) to intercept system back and dismiss the topmost enabled popup; only popups register it, dialogs do not. Predictive-back gesture scrubbing is native — closest is PopScope firing the standard exit animation. 2) Software keyboard: LocalSoftwareKeyboardController.hide() → FocusManager.instance.primaryFocus?.unfocus(); IME visibility via MediaQuery viewInsets.bottom. 3) Large-screen detection uses LocalWindowInfo.containerDpSize → MediaQuery.of(context).size (>=840w & >=480h). 4) Scrim pointer-consumption (every-frame consume) → AbsorbPointer / opaque Listener over full size; no ripple, no tap-dismiss. 5) staticCompositionLocalOf global registries → InheritedWidget or a global ChangeNotifier singleton. 6) Compose AnimatedVisibility with separate spring-enter/tween-exit specs has no 1:1 Flutter widget — drive manually via AnimationController (SpringSimulation forward, curved tween reverse) applying Opacity/Transform.scale/Transform.translate. 7) z-index stacking → ordered Stack children (or OverlayEntry order). No system blur involved (dim is a flat semi-transparent windowDimming color, fully replicable).

## 实现要点(keyNotes) — 严格按此复刻
FOUNDATIONAL — port this FIRST; it is the overlay/dialog/popup infra that Scaffold, Dialog, Popup, BottomSheet, ListPopup, Dropdown, Tooltip, Snackbar all depend on. It depends on NO other unported component (Scaffold/OverlayDialog imports are KDoc-only). Only color token used: colorScheme.windowDimming (already in list; has built-in alpha). No text styles.

ARCHITECTURE: In Compose, DialogLayout/PopupLayout render nothing — they REGISTER a state object into a global mutableStateListOf (provided via staticCompositionLocalOf), and MiuixPopupHost (placed in Scaffold's top z-slot) iterates those lists and renders each entry. Replicate with: (a) a registry — either an InheritedWidget (MiuixPopupRegistry) exposing 4 lists mirroring LocalPopupStates/LocalDialogStates/LocalRootPopupStates/LocalRootDialogStates, or a global ChangeNotifier singleton; (b) MiuixDialogLayout/MiuixPopupLayout as widgets returning SizedBox.shrink() that in initState/didUpdateWidget push+update a state and in dispose set showState=false (matching DisposableEffect onDispose); (c) a MiuixPopupHost widget that mounts a Stack of entries above content. `renderInRootScaffold` (default true) picks LocalRoot* list else Local* list — map to a root vs nested registry. `visible: MutableState<Boolean>` → ValueNotifier<bool>. When content==null: set visible=false and render nothing.

Z-INDEX: static counter nextZIndex starts at 1f, incremented per registered state (zIndex = nextZIndex++). Content drawn at zIndex; dim layer at zIndex-0.001; when no-dim, an invisible click-blocker at zIndex-0.002. Reset nextZIndex=1 only when both lists empty. In Flutter, order the Stack children by zIndex (sort dialogs then popups, each by zIndex). MiuixPopupHost iterates dialogStates THEN popupStates.

TRANSITION STATE MACHINE (per entry, replicate exactly): uses MutableTransitionState + pendingOpen + lastTarget. On showState=true: if animation NOT idle AND wasn't already opening (lastTarget false) → set pendingOpen=true (defer); else targetState=true. A second effect: when idle && pendingOpen → clear pendingOpen, targetState=true. On showState=false: pendingOpen=false, targetState=false. This debounces rapid toggles. In Flutter drive with an AnimationController.unbounded (or bounded 0..1); track isAnimating to gate pendingOpen. After exit completes (controller hits 0 / status dismissed), remove the state from the list AND (dialog only) invoke onDismissFinished — mirrors DisposableEffect onDispose that checks !showState.value.

EXACT ANIMATION SPECS (verbatim):
- Dialog dim ENTER: fadeIn tween(300ms, DecelerateEasing(1.5)). Dialog dim EXIT: fadeOut tween(250ms, DecelerateEasing(1.5)).
- Popup dim ENTER: fadeIn tween(300ms, SinOutEasing). Popup dim EXIT: fadeOut tween(150ms, SinOutEasing).
- Default dialog content ENTER, LARGE screen: fadeIn(spring dampingRatio=0.9, stiffness=438.6, visibilityThreshold=0.0001) + scaleIn(initialScale=0.8, SAME spring). SMALL screen: slideInVertically(initialOffsetY = full content height → slides up from bottom, spring dampingRatio=0.88, stiffness=450).
- Default dialog content EXIT, LARGE: fadeOut tween(200ms, DecelerateEasing(1.5)) + scaleOut(targetScale=0.8, tween(200ms, DecelerateEasing(1.5))). SMALL: slideOutVertically(targetOffsetY=full height, tween(200ms, DecelerateEasing(1.5))).
- Default popup content ENTER: fadeIn tween(200ms). EXIT: fadeOut tween(150ms).
Note enter uses SPRING but exit uses TWEEN for dialogs — controller must use SpringSimulation on forward and a curved duration tween on reverse. Build springs DIRECTLY as SpringDescription.withDampingRatio(mass:1, stiffness:438.6, ratio:0.9) and (mass:1, stiffness:450, ratio:0.88); do NOT route through folmeSpring (it derives stiffness from response — wrong here since stiffness is given). Equivalent response ≈ 0.300s (stiff 438.6) / 0.296s (stiff 450) if a response-based API is preferred. visibilityThreshold=0.0001 → SpringSimulation tolerance.

LARGE SCREEN: isLargeScreen = height>=480dp && width>=840dp (both). Uses windowInfo.containerDpSize → Flutter MediaQuery.of(context).size (width & height in logical px). effectiveLargeScreen = largeScreen && dialogState.enableAutoLargeScreen. Popups have NO large-screen variant.

DIM LAYER DRAWING: dialog dim draws drawRect(windowDimming.copy(alpha = windowDimming.alpha * dimAlpha)) where dimAlpha = dialogState.dimAlpha?.value.clamp(0,1) ?? 1 — supports a dynamic ValueNotifier<double> for interactive drag (bottom sheet) that bypasses the fade animation. Popup dim is just background(windowDimming), no dynamic alpha. In Flutter: ColoredBox/DecoratedBox with windowDimming, and for dialogs optionally windowDimming.withValues(alpha: windowDimming.a * dynamicAlpha).

SCRIM INPUT BLOCKING: both dim and no-dim branches wrap a fillMaxSize Box with pointerInput that consumes ALL pointer events every frame (blocks touches reaching content beneath) but does NOT dismiss on tap. Flutter equivalent: full-size AbsorbPointer, or opaque Listener/GestureDetector with HitTestBehavior.opaque. Dismissal is NOT via scrim tap here — only via back gesture (popups) or the content itself.

BACK HANDLER: ONLY PopupEntry has NavigationBackHandler (androidx.navigationevent) — isBackEnabled = enableBackHandler && (currentState||targetState), onBackCompleted sets showState=false. DialogEntry has NO back handler. Flutter: PopScope (Flutter 3.44) intercepting system back for the topmost enabled popup; predictive-back gesture animation is native, closest is PopScope + normal exit animation.

IME (dialog only): on dialog close, if WindowInsets.ime bottom>0 → keyboardController.hide(). Flutter: on dismiss, if MediaQuery.of(context).viewInsets.bottom>0 → FocusManager.instance.primaryFocus?.unfocus().

STATE FIELDS: DialogState{showState, zIndex, enterTransition?, exitTransition?, enableWindowDim=true, enableAutoLargeScreen=true, dimEnterTransition?, dimExitTransition?, dimAlpha:ValueNotifier<double>?, onDismissFinished?, content}. PopupState{showState, zIndex, enterTransition?, exitTransition?, enableWindowDim=true, enableBackHandler=true, dimEnterTransition?, dimExitTransition?, content}. Both entries wrap content in a fillMaxSize Box.

MOUNT POINT: MiuixPopupHost must sit above app content (Scaffold isn't ported yet). Mount it at app root (e.g. MaterialApp.builder wrapping child in a Stack with the host + registry) or in the future MiuixScaffold. Represent EnterTransition/ExitTransition as builder callbacks Widget Function(Animation&lt;double&gt; anim, Widget child) or a small spec class (fade/scale/slide flags + duration + curve/spring), since Compose EnterTransition/ExitTransition have no direct Flutter analogue.
